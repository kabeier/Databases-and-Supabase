Why Supabase?

The dashboard

See your tables and rows like a spreadsheet. Check Claude's work without writing SQL.

Auto-generated API

Create a table, get endpoints to read and write it. Your React app can use them right away.

Auth built in

Email, magic links, Google, GitHub. Weeks of work, already done.

An MCP server

Supabase maintains one for Claude Code. That's how Claude reaches your database.

Free tier

2 active projects, 500 MB, no credit card.

Plain PostgreSQL

Not a toy. The same engine big companies run.

Alternatives exist (your own server, AWS RDS, Railway). Supabase wins for us because you can see what Claude did.

Free tier tip for homework: 2 active projects is exactly one for your app and one for the Netflix clone. Free projects pause after about a week of no activity; you can resume them from the dashboard.

** LIVE, browser. ** Go top to bottom through the form and say each choice out loud. Students will copy this exactly for homework.

  • Organization: the folder your projects live in (plus billing and teammates). Supabase asks for one on the first sign-in: name, type Personal, Free plan. You already have one; point at the dropdown.
  • GitHub: leave it. That feature deploys database changes from SQL files in a repo; we build with Claude through the MCP instead. Your code still goes to GitHub with git as usual.
  • Database password: click Generate, Copy, paste into a password manager (or a note outside your project) before you click Create. Supabase never shows it again, but you can reset it in Project Settings → Database. We don't need it this week: Claude logs in through the MCP, and the API uses keys. Never put it in your repo or paste it into Claude.
  • Enable Data API: the auto-generated API from the last diagram. Keep it on; a future lecture uses it.
  • Automatically expose new tables: keep it on. The fine print recommends turning it off to control access by hand, but then the API can't see new tables until you grant access table by table. Row Level Security is our lock instead.
  • Enable automatic RLS: turn it on. Every new table gets Row Level Security automatically, even if someone forgets. "With RLS on and no rules, the API returns nothing. The rules come in future lectures."

** LIVE, about 5 minutes. ** This is the payoff for the diagram: "every rule we drew is now enforced by the database."

  • Table Editor → users → Insert row: your name and email. Leave id and created_at empty: the defaults fill them in. Point at the new UUID.
  • projects → Insert row: name "Databases". For user_id, Supabase offers a list of users to pick from, because it knows the foreign key. Try saving with no user_id first: it refuses (required).
  • tasks → Insert row: title "Finish the homework", pick the user and the project. is_complete defaults to false.
  • tags: add "school". task_tags: pick the task and the tag. "That row IS the many-to-many."
  • Break it: in task_tags, paste a made-up task_id (or try a second "school" tag). The database refuses: foreign key / unique violation. "Bad data can't get in."
  • SQL Editor: run the query on the slide. Read it like English.
  • Delete the Databases project. Back in tasks, the task is still there with an empty project_id: that's on delete set null.
