Why Supabase?

The dashboard

See your tables and rows like a spreadsheet. Check Claude's work without writing SQL.

Auto-generated API

Create a table, get endpoints to read and write it. Your React app can use them right away.

Auth built in

Email, magic links, Google, GitHub. Weeks of work, already done.

An MCP server

Supabase maintains one for Claude Code. That's how Claude reaches your database.

Free tier

2 active projects, 500 MB, no credit card.

Plain PostgreSQL

Not a toy. The same engine big companies run.

Alternatives exist (your own server, AWS RDS, Railway). Supabase wins for us because you can see what Claude did.

Free tier tip for homework: 2 active projects is exactly one for your app and one for the Netflix clone. Free projects pause after about a week of no activity; you can resume them from the dashboard.

The prompt

I'm building a task management application where people create projects and tasks, and label
tasks with tags. There are no logins yet, so everyone shares the same data. I have some
resources I'd like you to look at and supervise:

Here is my DrawSQL schema diagram (a screenshot): @task-manager-erd.png
Here are my user stories: @user_stories.md
My Supabase project is already connected in this directory through the supabase MCP.

Please:
1. Use the `postgresql-table-design` skill and the Context7 MCP to update your context on the
   documentation for Supabase and PostgreSQL.
2. Write the SQL schema for my diagram into `schema.sql`. Confirm it matches the diagram and the
   user stories, and list anything you'd change (including Row Level Security). Don't change my
   design on your own. Then stop.
3. After I approve, create the tables in my Supabase project ONE AT A TIME.
4. After each table, pause and tell me what you did so I can verify it in the dashboard.

Is there any additional information you may need from me?

The full text is in demo-kit/prompt.md. Read the four numbered steps out loud: research, write and review, build one at a time, pause after each.

"The pause-and-verify line is the most important line in this prompt. Claude can run ten commands in ten seconds. A wrong table is tedious to unwind."

The last line invites Claude to ask questions before it starts. Answer them out loud.

** LIVE, about 6 minutes. ** Open schema.sql and scroll it with the class. Take Claude's suggestions one by one: "agree" or "no, keep my diagram". Typical ones: indexes on FK columns (accept), defaults for created_at (accept), TEXT instead of VARCHAR (your call).

Live: explore your database in Supabase

Table Editor

  • Insert a project, then a task: pick its project_id from the list
  • Add a tag, then a task_tags row joining them
  • Break it: a task_tags row pointing at no task
  • Delete the project: the task stays, project empty
-- SQL Editor: every task with its project
select t.title, p.name as project
from tasks t
left join projects p
  on p.id = t.project_id;

Then: Database → Schema Visualizer

** LIVE, about 5 minutes. ** This is the payoff for the diagram: "every rule we drew is now enforced by the database."

  • Table Editor → projects → Insert row: name "Databases". Leave id and created_at empty: the defaults fill them in. Point at the new UUID.
  • tasks → Insert row: title "Finish the homework". For project_id, Supabase offers a list of projects to pick from, because it knows the foreign key. is_complete defaults to false.
  • tags: add "school". task_tags: pick the task and the tag. "That row IS the many-to-many."
  • Break it: in task_tags, paste a made-up task_id (or try a second "school" tag). The database refuses: foreign key / unique violation. "Bad data can't get in."
  • SQL Editor: run the query on the slide. Read it like English.
  • Delete the Databases project. Back in tasks, the task is still there with an empty project_id: that's on delete set null.

Optional, if you have a minute: ask Claude "How many tasks are in each project? Use the Supabase MCP, read only." Approve the query.

Delegate the typing, not the responsibility

  • Connect Claude to a development project, never production
  • Approve each Supabase tool call. Read it first.
  • Only looking? Add &read_only=true to the MCP URL
  • The secret (service_role) key never goes in front-end code
  • Keep Row Level Security on. Its rules come with the API.
